# 小学讲解、配音与 Manim 视频

先理解要教的知识或解对题，再写清讲解和画面，最后按真实配音渲染。不限于计算题，不需要为知识讲解虚构一道算术题。最终视频必须有配音，不能把静音片段或音频当成完整视频交付。

## Required capabilities

- `model-speech-synthesis`：当前模型配置启用的 TTS，不绑定供应商、音色或服务地址。
- `lesson-renderer`：独立 MCP，校验讲解计划、读取附件、Manim 渲染、FFmpeg 音画同步与发布成品。

Skill 导入只登记说明和资源，不自动安装依赖或运行 Python；上述工具需管理员登记并授权。
没有工具时说明缺项，不冒充已执行，也不读取密钥或获取管理员 Cookie。

## 工具名绑定

调用必须使用本轮工具表中的完整 `name`，不能把下面的逻辑操作名直接当成调用名。
下表是逻辑操作。通过授权能力目录查到本轮真实工具名并加载 Schema，随后用返回的完整名称调用。

| 逻辑操作 | 工具操作 |
| --- | --- |
| 保存并校验草稿 | `prepare_lesson` |
| 读取草稿局部 | `get_lesson_draft` |
| 局部修复草稿 | `patch_lesson_draft` |
| 合成配音 | `synthesize_speech` |
| 渲染成品 | `submit_lesson_render` |
| 查询原任务 | `get_lesson_render` |
| 取消原任务 | `cancel_lesson_render` |
| 图片文字识别 | `inspect_problem_image` |

工具已列在本轮 Schema 中，不另外调用不存在的 `list_tools`。名称被拒绝时核对本表与实际工具表，只修正名称和参数，不换名字盲试。

## 确定交付和题意

- 面向小学生的知识讲解、概念解释或题目辅导，默认先给几句适龄回答，再执行下面的完整配音动画流程；不因用户只用了“解释/讲解”而反问要不要视频。普通闲聊或非教学请求不适用这一默认行为。
- 用户明确“只要文字”“不要视频”时仅文字回答；明确只要音频时用已配置 TTS 合成完整讲解，不调用渲染工具。用户当前选择优先，不沿用旧对话的动画要求。
- 已有主题与年级就开始，不为可采用默认值的画面风格、时长重复澄清。缺少影响正确讲解的关键题干才询问；缺年级时说明采用的年级。需要分年级教学细则再读 [grades.md](grades.md)。
- 图片题目：已配置视觉模型能读取时使用其真实识别结果；否则将上传的 `attachment_id` 交给 `inspect_problem_image`。它是印刷文字 OCR，不能可靠理解手写、复杂公式或几何图形。返回 `requires_confirmation=true` 时，先展示识别到的题目请用户确认，再配音渲染；不能猜题。
- 用户未给具体数字的“讲解鸡兔同笼”等请求，可以明确选用一个简单示例；不能把示例说成用户原题。

## 一次准备本课讲解与视觉稿

先检查条件、运算、答案和验算。使用符合年级的思路；低年级优先画图、列表、假设和实际数量关系，不强塞超纲方程。

知识讲解先列清概念、它们的关系及容易混淆的地方，用孩子熟悉的比喻帮助理解，但说明比喻不是事实本身。按主题选择图形、比较卡片或分步呈现，不套用数学验算流程，不罗列无助理解的数字。示意图的尺寸或距离不按真实比例时明确标注。动画只使用工具实际支持的组件；不能承诺当前渲染器没有的三维模拟或精确运动效果。

教学动画不是配音幻灯片。先把核心讲解拆成“要观察的实体 → 它们的关系 → 需要看见的变化”，
使用 `scene` 的图形、分组与移动/旋转/缩放/高亮动作演示；物体可由多个基础图形组合。
标题、必要文字和小结可以静止，但不能用全文口播、比较卡片或淡入文字替代本来可以展示的过程。
不同实体要有独立的视觉表示，不能只在同一个圆圈旁贴多个名字。也不要为了凑动画让无关物体乱动。
本课首次编写 scene 时，先读取 [animation.md](animation.md) 再调用 prepare_lesson；已经读取过就复用，不要失败后才补读。里面给出完整参数层级及通用组合规则，不是题目模板。
本技能使用受控矢量组件，不需要调用图片/视频生成模型或编写可执行 Python。

调用一次 `prepare_lesson`，传完整 `lesson` 草稿对象：课题、原问题、年级、学科、分段口播和每段的 `visual`。参数是原生对象/数组，不是编码后的 JSON 字符串。入口允许保存尚有字段错误的草稿，不代表它已通过渲染契约校验。
每个 `segments[]` 元素只有 `id`、可选 `role`、`narration`、`visual`；`heading`、`caption`、`objects`、`groups`、`actions` 都在 `visual` 内。缩放写 `factor`，旋转必须写 `degrees`，不能换成 `to` 或省略动作的必填参数。
`show/hide` 是有持续时间的淡入淡出，不是瞬时开关；同一对象先显示再隐藏时，两次动作都写明确的 `start/end`，前者结束不晚于后者开始。省略 `end` 意味着持续到本段末尾 `1`。
一次准备本次讲解，按必要教学步骤分段；每段只讲一个动作或一组紧密相关的短句。简短知识问题不自动扩成完整课程：合并重复的比喻、比较和小结，不额外安排用户未要求的多轮练习或课后作业。需要详细课程时再按用户要求展开。画面用关键字、算式和图形，不把整段口播堆成一行小字。
开场先显示并读出本次完整题目（条件、材料和所求）；知识讲解则显示主题与本课要理解的问题，不能只有欢迎语。第一段用 `title` 的 `subtitle` 放题干或学习问题；题目较长时用连续的题目页显示，不能删去条件。自行选题时标注“示例题”，不得把示例冒充用户原题。答案放在推理之后，不在开场提前展示。

讲解要让孩子听懂“为什么”，不能把短句误解为只念结论：理解题意 → 建立直观联系 → 展开关键推理 → 回答问题 → 检查依据。根据学科、年级和题目选择方法；数学可验算数量关系，阅读题应结合原文说明依据，科学题解释观察与原因，不能都套数学算式。不是固定分段数，相邻步骤可合并，但不能跳过关键因果。每个讲解画面有当前问题或步骤标题，通常显示 2–3 行必要说明，或信息量相当的图表标签；不能只留一个结果。口播用几句短句讲清“观察/已知、理由、结论的含义”，与屏幕说明对应，不照搬成人口诀。说明过多时换页，不缩成难读的小字。

需要完整格式示例时，按需查 [examples.md](examples.md)。示例仅展示写法，不是题目路由表或固定模板；没有对应示例的题目也按本次输入编写，不固定数字、解法、段数或画面类型。

需要动作或答案精确对应一句讲解时，拆成不同段落；连续 scene 用 `continue_previous:true`
承接上一段最终画面，只传新的动作，不定义对象或分组。需要之后出现的对象，先在这个连续画面的第一段定义为 `visible:false`，后续用 `show` 揭示；若要改组成，就用新 scene，不声明接续。动画时长由工具读取配音确定，不传估算秒数。

渲染契约支持可组合的 `scene` 动画，也保留标题、文字、步骤、算式、分数图、数轴、比较卡片、几何、练习、表格和比例线段图；需要静态类型示例时只读 [reference.md](reference.md) 对应类型。不能提交 Python、Shell、任意文件路径或远程代码。
其中 `steps/bullets` 使用 `items:["文字", ...]`，不是 `steps` 字段或标题/正文对象数组。

### 根据保存结果继续，不重写整课

- `status=prepared`：校验通过，保留 `lesson_id` 和 `speech_requests`，进入配音。工具已保存不可变计划与组件快照，后续不再发送完整计划。
- `status=needs_repair`：草稿已持久化，但不能配音。保留 `draft_id` 和 `revision`，根据 `errors[].path/expected/current` 调用 `patch_lesson_draft`，只修正报错字段。路径相对于 lesson，例如 `/segments/1/visual/heading`，不带 `/lesson`。缺少角度等教学意图由本次画面设计决定，不由框架猜测。
- 检查点的 `repair_context.focus` 已提供当前错误涉及的精确局部数据时，直接修复，不再查询整课。工具声明仍需读取资料时，`get_lesson_draft(paths=[具体路径])` 只读取相关字段及约束；错误超过一页时用 `error_offset`。不重新读取整个技能或生成完整计划。补丁写法与版本冲突处理按需见 [draft-repair.md](draft-repair.md)。
- 每次补丁传最新 `expected_revision` 和原生 JSON `patches`。返回新版本后继续处理剩余错误；相同补丁重送不会重复应用。`patch_rejected` 时先看原因，不盲目重复。
- 没有获得 `status=prepared` 与 `lesson_id` 前不调用 TTS，不把“草稿保存”描述为视频已生成。JSON 本身无法解析时尚未保存草稿，先修正调用格式；不要虚构草稿 ID。

## 配音只生成一次，按段绑定

1. 按 `speech_requests` 调用本轮真实可用的 `synthesize_speech`，使用返回的 `arguments`，包含原文、文件名及 `artifact_visibility: "internal"`。这些分段配音是内部材料，不是交付成品。同一课使用当前配置的同一声音；不猜测实时 Schema 没有声明的参数。
2. 按 TTS 的实际返回格式保存引用，与 `segment_id` 一一对应。新版返回 `audio.url` 时，把完整签名地址原样传入 `artifact_url`；旧版实际返回 `artifact.attachment_id` 时使用 `attachment_id`。每段只选一种引用。`artifact-…` 与 `att_…` 是不同类型的 ID，绝对不能替换前缀、根据文件名编造 ID，或把 Artifact ID 填入附件字段。使用 `audio.url`，保留完整签名参数，不改成含 `download=true` 的下载地址。
3. 模型不手算 SHA-256、不下载 Base64、不自行编写音频清单。渲染 MCP 通过受限签名文件接口或兼容附件接口下载，验证来源文本摘要和文件摘要。
4. TTS 失败只处理失败段。成功段不重复合成；音频身份不匹配先检查绑定，只有改了口播或原调用确实失败才重新生成那一段。

没有词级时间戳时，每个口播段就是一个精确的画面段落。不能按字数均分并声称取得真实词戳；若要逐句变化，就按句拆段合成。

## 一次提交并等待完整视频

调用 `submit_lesson_render`：只传准备好的 `lesson_id` 和音频绑定。新版 TTS 使用 `audio: [{segment_id, artifact_url: 原样的 audio.url}, ...]`；旧版附件使用 `audio: [{segment_id, attachment_id: 原样的附件 ID}, ...]`。先核对实时 Schema 支持对应字段。默认清晰度和帧率由工具 Schema 提供，后续只传引用，不重复提交完整分镜或口播。

工具会验证全部音频，解码为 48kHz PCM，建立共同采样/帧时钟，以真实时长分配 Manim 的 `run_time`/`wait`，再合成带 AAC 配音的 MP4。每段末尾仅补不足一帧的静音，不用 `-shortest` 截断或长冻帧掩盖偏差。

提交结果声明持久化后台任务，Harness 自动查询并在 Chat 显示真实进度，**不需要模型反复查询、读取 Skill 或回答“继续等待”**。等待最终 ToolResult；普通人工查询使用 `get_lesson_render`，用户停止时使用工具声明的取消操作。

## 交付与局部恢复

- 只有状态 `completed` 且 `result.verified=true`，才能交付其中的最终 MP4。MCP 返回真实媒体 Artifact，Chat 据此展示视频和下载；不能把本地路径当成浏览器地址。
- 对话中的媒体只交付 **完整讲解音频 `speech.wav` 和带配音的完整视频 `final.mp4`**，使用最终 ToolResult 中的真实下载地址。音频是全部分段按真实时间轴拼成的，不重新调用 TTS 合成一遍。
- 不在对话输出分段 TTS 播放器/链接、旁白全文、计划清单、课程 ID、SRT、时间轴、校验 JSON 或 SHA-256；这些留在执行记录和服务文件中供恢复与排查。进度由真实工具事件展示，不逐段发送“第几段已合成”等文字。
- 简短回答解释本题关键知识或结论，不贴整份旁白或课程结构；前面已经回答过就不重复。随后提供“完整音频”和“完整视频”；已有成品卡片时不再重复罗列链接。用户明确只要成品时省略文字讲解。失败时如实说明失败环节，不能伪装完整交付。
- 渲染失败保留已生成音频和计划。先看具体错误，修复失败环节；明确重试时对原提交设置 `retry_failed=true`，不重新调用 TTS。
- 改画面需要重新 `prepare_lesson` 保存新计划；口播未变的段仍可绑定原音频。改口播只重新合成受影响段。
- `cancelled` 是工作进程确认停止后的状态。提交取消请求不等于已经停止，不在未知状态下另起重复任务。

对齐精度是句段/帧级，不宣称未实际取得的逐字或口型同步。本地脚本验证、音频绑定细节见 [reference.md](reference.md)。
