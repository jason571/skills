# 视频 MCP 执行与交付

只在用户明确要求生成视频时读本文件。镜头是单段 prompt 内的时间线，片段是一次生成调用，成片是实际合成后的交付物。**读取 Schema 和模型信息是只读预检；在确认多段成片路径前，不得启动任何付费生成。**

## 工具预检：不把规划当执行

1. 确认当前可见、已授权的 MiniMax H3 视频生成 MCP。从能力目录复制精确工具名，只按当前步骤加载所需 Schema，不猜前缀或把所有工具一并加载；必要时只调用一次其只读模型信息工具。优先用实际工具返回的单次时长范围、默认值、画幅、分辨率及参考模式；不要根据本文件或模型记忆制造数值。若选择了其他视频生成器，先告知用户这一变化。
2. 区分“单次生成即可交付”与“需要跨调用接帧、合成、保存音轨”。多段且要求完整 MP4 时，必须先确认已授权的持久化工作流确实绑定到本次选中的生成器，**或**末帧提取与时间线合成工具确实可以访问该生成器的产物 URL 并保留音轨。工具存在不等于其网络来源策略、权限或绑定已经满足。无法确认时，在第一笔生成前说明缺少的能力；不要先生成碎片再让用户自己拼。
3. 用户图片只有作为实际首帧/尾帧时才进入对应帧参数。普通参考用持续参考参数；若工具不支持该用途，说明限制而不暗中改成首帧。传给 MCP 的图片须为 MCP 能读取的 HTTP(S) 资源或该 MCP 明确支持的资产 ID，不传对方主机不可见的本机路径。

## 原生生成调用

对当前 MiniMax H3 MCP，常见工具为 `generate_video`（保持调用打开，MCP 直接推送进度）或 `submit_video_generation` → `get_video_job` / `get_video_result`（分离任务）；实际完整名称和字段以注册时的工具目录及实时 Schema 为准。对于一次可完成的短剧，将本段**全部镜头**写入一份 `prompt`，只提交一次。不要把四个镜头误当四个视频任务，也不要调用生成工具探测默认值。

按用户需求与实时 Schema 映射参数：`prompt_mode` 选择 H3 结构模式；`duration_seconds` 是**一段生成时长**而非每镜时长；`aspect_ratio`、`resolution`、`audio_enabled` 是结构化控制；`negative_prompt`、`soundscape` 分别承载反向约束与声音计划。首帧、尾帧和持续参考分别使用相应的 `first_frame_url`、`last_frame_url`、`reference_image_url` 或 Schema 声明的资产 ID；省略不存在或未使用的字段，不用 `null` 占位。若当前 Schema 改名或不支持，服从 Schema 而不是硬套这些示例名称。除用户明确要求无声外，短剧应保留同期声音；如果要精确的外部配乐或旁白，应确认独立混音能力，不声称 H3 自带音轨等于指定的音乐。

多段路线择一，不混用：

- 已确认受管完整视频工作流绑定本次 MiniMax 生成器：把**全部有序片段计划一次**交给该工作流；每段的 `generation` 是经实时生成器 Schema 校验的原生参数。后段的实际首帧由工作流从上一段结果提供，不填原始参考图为首帧。工作流返回检查点后按其要求恢复，不能重新提交整个计划。
- 使用直连生成器和独立衔接/合成工具：按计划顺序每段恰好提交一次；取得成功结果的真实 MP4 URL 后，提取其末帧，把**末帧 URL**作为下一段首帧；最后用可访问这些 URL 的时间线合成工具按顺序拼成一个 MP4，显式保留源音轨。中间片段与衔接帧若工具支持，标记为内部产物，不自动展示给用户。

同一段存在已受理 `job_id` 时只查询它，不再提交。提交结果不明、URL 不可访问、片段失败或工作流返回错误时，保存/沿用已有检查点；只修正失败部分，未经核实不重复付费调用。取消时使用已返回的取消工具和 `job_id`，不把“停止模型回答”当作视频任务已取消。页面进度由 MCP 通知或查询结果提供，Skill 不让模型重复口播百分比。

## 交付检查

单段视频的最终 URL 必须来自该段已完成结果；多段最终 URL 必须来自实际合成结果。核对目标片段数、时长、宽高、音轨状态与工具/产物元数据一致后再描述。仅有 `job_id`、计划或中间片段时报告对应状态，不宣称成片已完成。最终对话只展示成片；如用户需要分镜表或独立片段，再额外提供。
