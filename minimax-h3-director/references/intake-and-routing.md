# 需求问询与模式路由

先用用户的语言理解目标，再引入缩写。问询的目的不是收集一张表，而是消除会改变结构的歧义。

## 最小问询模板

只问会改变执行方式、付费规模或成片内容的缺失信息。以下问题按需选用，不必一次全问：

```text
我先确认四件事，避免把素材接错：
1. 如果素材角色仍不明确：这张图/这段视频是成片中的实际首尾画面，还是角色、风格、动作或音色参考？
2. 目标时长和画幅是什么？
3. 剧情中必须看见哪些动作、物件和转场？
4. 是否有逐字台词、歌声、画面文字或声音限制？
```

若用户已回答其中一项，不要重复提问。回答后用一句话确认路由，例如：`我会用 FL2VA：第一张图锁定起点，第二张图锁定结尾，重点描述两者之间的连续动作。`

## 选择树

1. 没有媒体资产：选择 T2VA。
2. 图片或视频资产是否必须成为成片的具体画面？
   - 是，且是第一个画面：I2VA。
   - 是，且给了开头与结尾：FL2VA。
   - 是，且只锁定结尾：L2VA。
3. 资产仅提供角色身份、服装、场景、风格、动作来源、剪辑节奏或声音？选择 R2V / full-reference。
4. 用户只称图片为“参考”时，按语义参考处理，不自动设为首帧；若同时有“从这张图开始/最后停在这张图”等要求，再设为关键帧。两种解释都与用户原话相容且会改变执行时，暂停并问一个简短问题；不要根据文件名或人物居中等弱信号猜测。

## 常见口语映射

| 用户说法 | 需要确认的解释 |
| --- | --- |
| “让这个人说一句话” | 默认把图当人物身份参考；若要求从原图画面开始，再改首帧；确认逐字台词 |
| “从 A 变成 B” | A/B 是否分别是首尾帧；中间是否允许切镜 |
| “最后定格在这张图” | 通常是 L2VA，但仍确认是否允许从另一个状态开始 |
| “按这个视频的感觉做” | 是复用动作/剪辑结构，还是只参考美术风格 |
| “像这个角色，但换个场景” | 通常是 R2V，而不是 I2VA |

## 交付前复核

在写提示词前，确认模式、素材角色和逐字台词。文本策划可以对非关键时长/比例采用明确标注的合理假设；实际生成则读取视频 MCP 的实时 Schema 与默认值。只在缺失项会改变路由、标签编号或多段成本时询问，不让可选细节阻塞创作。
