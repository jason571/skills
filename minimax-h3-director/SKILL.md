# MiniMax H3 Director

先判断交付目标：**策划/分镜/提示词**只输出文本；**生成视频/完成短剧**才调用已登记且获授权的能力。不要把读到 Skill、写好提示词或取得任务 ID 说成视频已完成。不得修改 Harness、安装能力或假定某个 MCP 一定存在。

## 从一句话到短剧

用户给一句设想即可开始创作，不必先索取完整剧本。保留用户指定的题材、人物、地点、画风、语言和结局；其余细节可以创作，但不能把猜测写成参考素材的可见事实。先确定主角的目标、阻力、转折与结局，再写**一次完整的**场次/片段计划；每段说明剧情推进、人物与道具状态、镜头时间线、声音和结束画面。后段必须从前段已发生的结果继续，不能反复回到开场或重复同一冲突。人物身份、服装、时空、屏幕方向、道具和声音使用稳定的连续性锚点；仅在剧情要求变化时明确写出过渡。

一段生成调用可以含多个镜头；**镜头不是生成任务**。镜头数由动作和时长决定，不为了凑数量切碎连续动作。每镜写可见动作、景别/主要运镜、声音及结束状态，切点时间严格递增并落在该段时长内。需要对白时可以创作原创台词并逐字写出，但不得把原创台词当作用户原话，也不得捏造已有歌曲的歌词。按 [短剧规划](references/short-drama-production.md) 制作可复用的剧情总纲、连续性表和分段计划。

## 素材与 H3 模式

按 [需求与模式路由](references/intake-and-routing.md) 区分 T2VA、I2VA、FL2VA、L2VA 和 R2V。用户只说“参考图片”时，它是**视觉参考，不自动成为首帧**；只有明确指定开场/结尾画面才使用相应帧参数。若视觉内容对剧情重要，先用已授权读图能力确认可见事实；没有读图能力时，不声称看见了图中人物或场景，只能依据用户文字写作。若图片用途确实会改变执行方式且无法从语境判断，再问一个简短问题。

基础模式按 [base-modes.md](references/base-modes.md)，持续参考按 [reference-mode.md](references/reference-mode.md)；写法按 [prompt-spec.md](references/prompt-spec.md)。保留 H3 提示词的结构、时间线、角色标签和语言要求，但最终工具参数必须服从**当前被选中 MCP 的描述与输入 Schema**，不能凭 Skill 猜测支持的模式、时长、画幅、分辨率或默认值。只有需要核对模型版本或许可时读 [official-resources.md](references/official-resources.md)。

## 真实生成

只在用户要求出片时阅读 [视频 MCP 执行与交付](references/video-mcp-execution.md)。先确认视频生成 MCP、必要的衔接/合成能力及权限；读取实时 Schema，并在需要时调用其只读模型信息工具取得时长和格式约束。把用户明确控制的画幅、时长、声音、首尾帧、持续参考素材放进**原生工具参数**，不是只写在 prompt 中。若总时长可由一次调用完成，提交整个多镜提示词**一次**；超出单次上限时，先完成全部分段剧情和提示词，再选择具备持久化、真实末帧衔接与音频保留的工作流。无法确认最终成片能力时，在付费生成前说明缺口，不以碎片视频冒充完整短剧。

优先保留 MCP 原始进度和错误；不要让模型编造进度。已受理的任务只用其 `job_id` 查询或取消；成功片段不重生成，提交结果不明时停止并从已保存状态核对，不盲目重试。只交付实际完成的产物；失败时指出具体阻断点和可恢复状态，不改写 MCP 的业务错误。

## 输出

策划请求只交付用户要求的剧情、分镜或 H3 提示词，不为“只写剧情”强加技术参数，也不假装调用了工具。生成请求先简要说明路线，成功后优先交付**一个最终成片**及必要的时长/尺寸/音频事实，这些事实只引用工具结果或产物元数据；中间片段、末帧和内部任务 ID 不作为最终成片展示。不要声称本 Skill 是 MiniMax 官方产品，或把未执行的 ComfyUI/后期步骤说成已完成。
